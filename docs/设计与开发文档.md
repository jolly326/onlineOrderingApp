# 详细设计与开发文档

## 一、系统架构设计
### 1.1 整体架构
采用前后端分离三层架构：
- **表现层**：Vue 3 + Vant 4 构建的单页应用，负责用户交互与页面渲染
- **业务逻辑层**：Django REST Framework 提供RESTful API，处理核心业务逻辑
- **数据访问层**：Django ORM + MySQL，负责数据存储与查询

### 1.2 数据流
```
用户操作 → 前端页面 → Axios请求 → 后端API → 业务逻辑 → ORM操作数据库
          ↓
前端更新页面 ← JSON响应 ← 后端处理结果 ← 数据返回
```

## 三、核心业务流程
### 3.1 点餐全流程
1. 用户浏览菜品 → 加入购物车 → 进入购物车
2. 系统校验：购物车非空且无已下架菜品
3. 提交订单 → 生成待支付订单和支付记录
4. 用户选择支付方式 → 发起模拟支付
5. 支付成功：
   - 更新订单状态为"备餐中"
   - 清空购物车
   - 商家收到新订单
   - 商家备餐完成 → 出餐 → 状态变为"待取餐"
   - 生成取餐码
   - 用户到店出示取餐码 → 商家输入取餐码确认 → 订单完成
6. 支付失败：提示重试
7. 15分钟未支付：自动取消订单

### 3.2 订单状态流转
```
待支付 →（支付）→ 备餐中 →（商家出餐）→ 待取餐 →（商家输入取餐码）→ 已完成
    ↓
（超时15分钟）→ 已取消
```

## 四、API接口设计
### 4.1 接口规范
- 基础URL：`http://127.0.0.1:8000/api/v1/`
- 请求/响应格式：JSON
- 认证方式：请求头 `Authorization: Bearer {token}`
- 统一响应：`{ "code": 200, "message": "success", "data": {} }`

### 4.2 核心接口
#### 用户模块
- `POST /users/register`：注册（支持role字段）
- `POST /users/login`：登录
- `GET /users/profile`：获取用户信息
- `PUT /users/profile`：修改用户信息

#### 菜品模块
- `GET /dishes`：获取上架菜品列表（?category=xxx）
- `GET /dishes/all`：获取所有菜品（含下架，商家）
- `GET /dishes/{dishId}`：获取菜品详情
- `POST /dishes/create`：新增菜品（商家，multipart）
- `PUT /dishes/{dishId}/update`：更新菜品（商家，multipart）
- `PUT /dishes/{dishId}/status`：上下架菜品（商家）
- `DELETE /dishes/{dishId}/delete`：删除菜品（商家）

#### 购物车模块
- `GET /cart`：获取购物车
- `POST /cart/add`：添加菜品
- `PUT /cart/item/{itemId}`：修改数量
- `DELETE /cart/item/{itemId}`：删除菜品
- `DELETE /cart/clear`：清空购物车

#### 订单模块
- `POST /orders/create`：提交订单
- `GET /orders/`：获取订单列表（?status=xxx）
- `GET /orders/count`：获取用户订单数量统计
- `GET /orders/{orderId}`：获取订单详情
- `GET /orders/merchant`：商家获取所有订单
- `GET /orders/merchant/stats`：商家获取经营统计
- `PUT /orders/{orderId}/status`：更新订单状态（商家，备餐→待取餐）
- `PUT /orders/merchant/confirm-pickup/{orderId}`：商家确认取餐（验证取餐码）

#### 支付模块
- `POST /payments/pay`：发起支付
- `GET /payments/status/{payId}`：查询支付状态

## 五、模块详细实现
### 5.1 用户模块
- **后端**：使用SimpleJWT实现JWT认证；通过role字段区分用户和商家；注册时可选角色
- **前端**：登录页、注册页（含角色选择）、个人中心页；token存储在sessionStorage，按Tab隔离

### 5.2 菜品模块
- **后端**：菜品列表支持分类筛选；图片上传到`media/dishes`目录并持久化；图片路径存入`images` JSON字段（images[0]为主图）
- **前端**：首页分类导航+菜品卡片；菜品详情页；商家端统一管理页含菜品Tab（带开关按钮和新增/编辑弹出层）

### 5.3 购物车模块
- **后端**：用户注册时自动创建购物车；添加菜品时合并相同菜品；获取购物车时自动过滤下架菜品
- **前端**：购物车页显示菜品列表、数量调整、总价；底部导航显示购物车角标

### 5.4 订单模块
- **后端**：订单号 `yyMMdd + 8位随机数`；使用 `__range` 按本地时区过滤今日订单；`refresh_daily_stats()` 在订单创建/状态变更时自动刷新每日统计
- **前端**：用户订单列表页（按状态标签分类）、订单详情页；商家统一管理页含订单Tab（出餐、取餐码验证）

### 5.5 支付模块
- **后端**：模拟支付接口90%概率返回成功；支付成功后触发订单状态更新和购物车清空
- **前端**：支付选择页与结果页合并为单页面（内联展示支付结果）

### 5.6 商家统计模块
- **后端**：`DailyStats` 表按天持久化经营数据；`refresh_daily_stats()` 在订单变更时自动重新计算
- **前端**：商家管理页概况Tab展示今日订单数、今日收入、各状态待处理卡片

## 六、设计模式应用
1. **MVC模式**：Django原生架构，分离Model、View
2. **RESTful架构**：统一API设计风格
3. **工厂模式**：支付处理器工厂，根据支付类型创建对应处理器
4. **观察者模式**：订单状态变化时触发统计刷新

## 七、编码规范
### 7.1 后端（Python）
- 遵循PEP 8规范
- 类名大驼峰，函数/变量蛇形命名
- 使用ORM操作数据库，禁止原生SQL
- 所有接口添加异常处理

### 7.2 前端（Vue）
- 遵循Vue 3官方规范，使用`<script setup>`语法
- 组件名大驼峰，变量/函数小驼峰
- 接口统一封装在`api`目录
- 使用Pinia管理全局状态
