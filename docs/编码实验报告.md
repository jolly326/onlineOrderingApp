# 编码实现实验报告

## 一、项目简介

### 1.1 项目背景

本项目为软件工程课程作业第三阶段（编码实现），基于已完成的需求分析和详细设计，开发一个**单商家自营到店取餐在线点餐平台**。参考瑞幸咖啡、喜茶GO等主流微信小程序的业务模式，聚焦移动端Web体验，实现从浏览菜单到取餐的完整业务闭环。

### 1.2 系统定位

- **业务类型**：饮品/快餐类自营到店取餐平台
- **技术形态**：纯移动端Web应用（适配手机浏览器，无需原生APP）
- **核心场景**：用户线上浏览 → 加购下单 → 模拟支付 → 商家备餐 → 用户取餐
- **服务对象**：普通用户（点餐取餐）、商家（管理菜品、处理订单）
- **MVP目标**：100%覆盖需求分析中所有高优先级User Story，实现可运行的最小可行系统

### 1.3 技术栈

| 层级 | 技术选型 | 版本 | 用途 |
|------|----------|------|------|
| 前端框架 | Vue.js | 3.x | 前端MVVM框架 |
| 前端UI | Vant | 4.x | 移动端组件库 |
| 前端构建 | Vite | 8.x | 开发服务器与打包 |
| 状态管理 | Pinia | 3.x | 用户信息、购物车状态 |
| HTTP客户端 | Axios | 1.x | API请求封装 |
| 后端框架 | Django | 4.2 | Web框架 |

| 认证 | SimpleJWT | 5.x | JWT Token认证 |
| 数据库 | MySQL | 8.0+ | 数据持久化 |
| 跨域 | django-cors-headers | 4.x | CORS配置 |
| 图片处理 | Pillow | 12.x | 图片上传处理 |
| AI辅助工具 | DeepSeek | — | 代码生成、调试辅助 |

## 二、VibeCoding 过程

### 2.1 初始 Prompt

```
开发一个单商家自营到店取餐在线点餐平台MVP，使用Django + Vue 3技术栈，前后端分离。
要求：
1. 用户可手机号注册登录，支持普通用户和商家两种角色
```

### 2.3 VibeCoding 模式总结

整个开发过程遵循以下循环：

```
需求分析 → Prompt工程 → AI代码生成 → 本地运行测试 
    ↓                        ↑
    └── 发现问题 → 定位根因 → 修改Prompt再生成
```

**关键经验**：
1. **Prompt粒度控制**：一次只描述一个功能模块，避免AI生成混乱
2. **上下文管理**：每次Prompt附上当前项目状态，避免AI偏离已有架构
3. **渐进式UI打磨**：先保证功能可用，再迭代UI细节
4. **Bug修复策略**：遇到bug时先手动定位根因，再给出精确的修复Prompt

## 三、AI生成后的修改与问题

### 3.1 功能层面的修改

| 修改项 | 原始AI方案 | 人工修改 | 原因 |
|--------|-----------|----------|------|
| 注册角色选择 | 仅用户名+密码注册 | 增加"我要点餐/我是商家"卡片 | 需区分用户和商家入口 |
| 用户/商家导航栏 | 白色 vs 深色不同风格 | 统一深色渐变风格 | UI风格一致性 |
| 支付结果页 | 独立PayResult.vue页面 | 合并到Payment.vue内联展示 | 减少页面跳转 |
| 商家页面数量 | 4个独立页面 | 合并为2个页面（Tab切换） | 简化操作路径 |
| 评价功能 | 完整评价提交/查看页面 | 全部删除 | 业务文档无此需求 |
| 取餐确认流程 | 用户端"确认取餐"按钮 | 商家输入取餐码确认 | 对齐业务文档 |
| 经营统计 | 实时ORM聚合查询 | DailyStats持久化表 | 避免每次实时计算 |
| 图片字段 | ImageField单图 | images JSON数组(images[0]为主图) | 去除冗余，预留多图 |

### 3.2 修复的关键Bug

| Bug | 现象 | 根因 | 修复方案 |
|-----|------|------|----------|
| CORS网络错误 | 前端弹出"网络错误，请稍后重试" | 前端运行端口不在CORS白名单 | `CORS_ALLOW_ALL_ORIGINS = True` |
| 统计一直为0 | 商家今日订单数和收入始终显示0 | Django `__date` 查询在MySQL+时区环境下失效 | 改为 `__range` 传入本地时区起止时间 |
| 取餐码错误显示成功 | 输入错误取餐码仍提示"取餐成功" | 异步错误被catch静默吞掉 | 显式检查API返回code，catch中提取错误消息 |
| 用户名重复注册 | 同用户名可注册多个账号 | 序列化器缺少validate_username | 添加用户名唯一性校验 |
| 购物车图片不显示 | 购物车中菜品图片为空白 | CartSerializer未传入request上下文 | 5处调用全部添加context |
| 编辑删除图片失败 | 点击删除按钮后图片仍在 | 前端未向后端发送删除标记 | 新增remove_image参数 |
| 登录状态丢失 | 登录后自动跳回登录页 | 路由守卫读取localStorage但store写sessionStorage | 路由守卫改为sessionStorage |

### 3.3 遗留问题

| 问题 | 影响 | 优先级 | 说明 |
|------|------|--------|------|
| 密码明文存储 | 安全性低 | 中 | 当前注册和登录均使用明文比较，未使用Django的set_password/check_password |
| 支付超时未实现 | 业务不完整 | 中 | pay_deadline字段存在于模型中，但无定时任务实现15分钟自动取消 |
| 无分页 | 大量订单/菜品时性能差 | 低 | 缺少分页API支持 |
| 图片文件名冲突 | 同名文件上传会覆盖 | 低 | 当前使用get_valid_filename未添加UUID前缀 |
| 虚拟环境缺失 | 首次部署需手动安装依赖 | 低 | 未提供requirements.txt的自动安装脚本 |

## 六、运行说明

### 6.1 环境要求

- Python 3.10+
- Node.js 18+
- MySQL 8.0+
- 现代浏览器（Chrome/Firefox/Edge）

### 6.2 启动步骤

```bash
# 1. 创建MySQL数据库
mysql -u root -p -e "CREATE DATABASE onlineOrder CHARACTER SET utf8mb4;"

# 2. 配置后端
pip install -r backend/requirements.txt
# 创建 backend/config.json（模板见配置文档）
python manage.py migrate
python manage.py runserver
# 后端启动在 http://localhost:8000

# 3. 配置前端
cd frontend
npm install
npm run dev
# 前端启动在 http://localhost:5173
# 按F12打开手机模拟模式
```
